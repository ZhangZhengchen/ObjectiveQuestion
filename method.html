审阅背景，不属于学生题面 / Reviewer context, not part of the student question

边界条件与特殊输入的测试

程序容易在类别交界或特殊位置出错，例如零值、空集合、首尾元素和数值上限。设计测试时，应把这些边界作为明确的子域，而不只选择普通的中间值。

本题保留考察：选择一项精简修订：它能够有理有据地用相关边界子域扩展当前测试套件，为有效输入给出规范支持的结果，并且不对空数组作出无依据的承诺。

Boundary cases as explicit testing subdomains

Include boundary subdomains such as empty collections, zero, numeric extremes and first/last positions, where behaviour may change abruptly.

Retained judgment: Choose the compact revision that defensibly expands the current suite with relevant boundary subdomains, gives specification-supported results for valid inputs, and makes no unsupported promise for an empty array.

来源 / Source: Reading 3: Testing · Include Boundaries in the Partition

子域是指预期表现相似的一类输入。方法 latest(int[] years) 要求数组非空，并返回其中的最大值。当前测试为 [1990,2020]→2020、[2020,1990]→2020 和 [2000,2000]→2000。元素可以包括 0、Integer.MIN_VALUE 和 Integer.MAX_VALUE。以下哪项精简修订最恰当地补充了不同的遗漏边界覆盖，并给出了有依据的预期？

A添加 [1980, 2020]→2020 和 [2020, 1980]→2020；对于 []，预期为 0。
B添加 [0]→0 和 [Integer.MIN_VALUE, Integer.MAX_VALUE]→Integer.MAX_VALUE；[] 不符合非空要求，因此不承诺任何结果。
C添加 [0]→0 和 [Integer.MIN_VALUE, Integer.MAX_VALUE]→Integer.MIN_VALUE；[] 不符合非空要求，因此不承诺任何结果。
D添加 [0]→0、[Integer.MAX_VALUE]→Integer.MAX_VALUE 和 []→抛出异常。

整题完全匹配计分，不计部分分。

A subdomain is a category of inputs expected to behave similarly. Method latest(int[] years) requires a nonempty array and returns its greatest value. Current tests are [1990,2020]→2020, [2020,1990]→2020, and [2000,2000]→2000. Elements may include 0, Integer.MIN_VALUE, and Integer.MAX_VALUE. Which compact revision best adds distinct omitted boundary coverage with supported expectations?

AAdd [1980, 2020]→2020 and [2020, 1980]→2020; for [] expect 0.
BAdd [0]→0 and [Integer.MIN_VALUE, Integer.MAX_VALUE]→Integer.MAX_VALUE; [] is outside the nonempty requirement, so no result is promised.
CAdd [0]→0 and [Integer.MIN_VALUE, Integer.MAX_VALUE]→Integer.MIN_VALUE; [] is outside the nonempty requirement, so no result is promised.
DAdd [0]→0, [Integer.MAX_VALUE]→Integer.MAX_VALUE, and []→an exception.

Whole-item exact match; no partial credit.

参考答案与解释 / Reference answer and explanation

B (添加 [0]→0 和 [Integer.MIN_VALUE, Integer.MAX_VALUE]→Integer.MAX_VALUE；[] 不符合非空要求，因此不承诺任何结果。)

B 添加了有效测试，覆盖零和两个整数极值，并给出了正确的最大值预期。它还避免对无效的空输入承诺行为。A 重复了普通的顺序覆盖，并杜撰了空输入的结果。C 对最大值的预期不正确。D 杜撰了空数组会抛出未规定的异常，并遗漏了最小整数边界。

B (Add [0]→0 and [Integer.MIN_VALUE, Integer.MAX_VALUE]→Integer.MAX_VALUE; [] is outside the nonempty requirement, so no result is promised.)

B adds valid tests covering zero and both integer extremes, with correct greatest-value expectations. It also avoids promising behavior for the invalid empty input. A repeats ordinary ordering coverage and invents an empty-input result. C has an incorrect expected greatest value. D invents an unspecified exception for the empty array and omits the minimum integer boundary.

五阶段设计记录 / Five-stage design record

步骤1：表现目标

评价一项简洁的修订，该修订补充了相关但遗漏的边界情况，并给出正确的预期结果。

对覆盖范围和预期结果作出一个综合比较；提供普通案例事实，但边界测试的支配规则仍应属于已学知识。

Stage 1: performance claim and observable evidence

Evaluate a compact revision that adds relevant omitted boundary cases with correct expected results.

One integrated comparison of coverage and expectations; ordinary case facts are supplied, but the governing boundary-testing rule remains learned knowledge.

步骤2：情境与开放任务

库方法 latest(int[] years) 要求数组非空，并返回其中的最大值。当前测试为 [1990, 2020]→2020、[2020, 1990]→2020 和 [2000, 2000]→2000。数组可以包含 0、Integer.MIN_VALUE 或 Integer.MAX_VALUE。子域是指预期表现相似的一类输入。

作为测试评审人员，请为开发人员编写一份精简修订。将当前测试套件与相关边界子域进行比较，然后添加不超过三个测试。对于每项新增测试，请给出输入、预期结果和所覆盖的边界。说明你的修订为何改善了覆盖。明确处理空数组，但不要假定规范未承诺的行为。

Stage 2: scenario and open task

A library method latest(int[] years) requires a nonempty array and returns its greatest value. The current tests are [1990, 2020]→2020, [2020, 1990]→2020, and [2000, 2000]→2000. Arrays may contain 0, Integer.MIN_VALUE, or Integer.MAX_VALUE. A subdomain is a category of inputs expected to behave similarly.

As a test reviewer, write a compact revision for the developer. Compare the current suite with relevant boundary subdomains, then add no more than three tests. For each addition, give the input, expected result, and boundary covered. Explain why your revision improves coverage. Address the empty array explicitly without assuming behavior not promised by the specification.

role: Test reviewer

audience: Developer

situation: The existing suite checks order and equality but may omit important boundary subdomains.

开放任务的产物与成功标准

一份比较以及添加不超过三个测试的修订套件

  • 识别相关的遗漏边界子域。
  • 为新增的有效输入提供正确的预期结果。
  • 将每项新增测试与一个明确说明的边界相关联。
  • 以符合所述要求的方式处理空数组。
  • 说明该修订如何添加不同的覆盖，而不是重复一个普通类别。

Open-task product and success criteria

A comparison and revised suite with up to three added tests

  • Identifies relevant omitted boundary subdomains.
  • Provides correct expected results for valid added inputs.
  • Links every addition to a stated boundary.
  • Treats the empty array consistently with the stated requirement.
  • Explains how the revision adds distinct coverage rather than repeating an ordinary category.

步骤5：响应设计 / Stage 5: response design

题型理由

单项选择适合保留的有界决策。恰好有一个候选项能够满足所有标准，同时原则上仍允许组合边界或单独测试边界等合法测试设计方法。保留的评估操作 O3 使从编写到评估的转换具有合理依据。

未保留的表现

  • 独立编写测试输入、预期结果和边界标签。
  • 由学习者撰写对覆盖改进的说明。
  • 直接展示多个合法的编写方案。

Format rationale

Single choice fits the retained bounded decision. Exactly one candidate can satisfy all criteria while allowing legitimate test-design approaches, such as combining or isolating boundaries, to remain valid in principle. The retained evaluation operation O3 makes the production-to-evaluation conversion defensible.

Performance not retained

  • Independent production of test inputs, expected results, and boundary labels.
  • A learner-authored explanation of the coverage improvement.
  • Direct demonstration of multiple legitimate production solutions.
